# Семинар 12. Сколько стоит портфель?

Студенты начинают с оценки портфеля на `Future`, выражают те же зависимости через `CompletableFuture`, а затем меняют платформенные потоки на виртуальные. Все три версии получают позиции, параллельно запрашивают котировки и курсы валют, считают итог и сообщают, если поставщик подвёл. В конце группа самостоятельно исправляет один дефект многопоточного кода.

## 1. От Future к CompletableFuture

Перед занятием соберите модуль `advanced` на JDK 25 и запустите локальный MockServer по [инструкции](../../COMMANDS.md#семинар-12-оценка-портфеля). Для P1 три акции T по 100 рублей и две акции AAPL по 10 долларов при курсе 90 дают 2100 рублей. Для P2 данные те же.

Если группа помнит клиент прошлых семинаров, напомните его контракт. `TInvestApiClient.fetchQuotes()` читает весь список инструментов из `/v1/instruments`. В этом примере [PortfolioMarket](../../../src/main/java/academy/backend/market_pulse/client/PortfolioMarket.java) запрашивает состав конкретного портфеля, цены выбранных тикеров и нужные курсы валют.

1. На слайде 7 откройте [PortfolioServiceV1.evaluateOne](../../../src/main/java/academy/backend/market_pulse/service/portfolio/PortfolioServiceV1.java). После загрузки состава портфеля задача отправляет запрос котировок в executor и сама запрашивает курсы. Найдите `prices.get()`. Спросите, после какого вызова у нас есть оба результата.
2. В [PortfolioServiceV2.evaluateOne](../../../src/main/java/academy/backend/market_pulse/service/portfolio/PortfolioServiceV2.java) проследите тот же путь от `supplyAsync` через `thenCompose` к `thenCombineAsync`. Для загрузки данных и для расчёта указаны исполнители. По `--trace` сопоставьте их с именами потоков. При сравнении V1 и V2 итог и порядок портфелей совпадают.
3. **По времени, слайд 10.** Откройте [CallableCallbackDemo](../../../src/main/java/academy/backend/market_pulse/demo/concurrency/CallableCallbackDemo.java). Перед запуском спросите, в какой момент в очередь попадает `processQuotes`. Запустите `main` и проследите вложенные вызовы от внешнего `submit` до `println`. Когда `getQuotes` получает цены, его callback отправляет обработку в тот же `dispatcher`. После расчёта `processQuotes` вызывает свой callback, и тот печатает `900 RUB`. Покажите два `get()` в `main`. Первый возвращает Future обработки, второй ждёт вывода. Что случилось бы, если бы единственный рабочий поток стал ждать вторую задачу? Вернитесь к графу `CompletableFuture` на **11**.
4. Вернувшись к слайдам, попросите группу на **15** отличить обычное преобразование значения от запуска нового отложенного вычисления. На **18** покажите, куда передать свой executor. На **20** отделите отмену стейджа от прерывания работы уже запущенной задачи.

## 2. Что увидит вызывающий код при ошибке

На слайде **22** возьмите один неуспешный стейдж. `whenComplete` позволяет записать исход в лог. Если наблюдатель отработал успешно, ошибка проходит дальше. `exceptionally` может подставить значение при сбое. `handle` строит новый результат и при успехе, и при ошибке. Для подготовки можно открыть [контракт CompletionStage](https://docs.oracle.com/en/java/javase/25/docs/api/java.base/java/util/concurrent/CompletionStage.html), [разбор на Habr](https://habr.com/ru/articles/784144/#exceptions), [примеры Baeldung](https://www.baeldung.com/java-exceptions-completablefuture).

На **23** предложите ситуацию. Цена пришла, а курс не успел прийти до таймаута. Вызовется ли функция в `thenCombine`? Что увидим при вызове `join()`? Откройте [PortfolioExceptionsDemo.show](../../../src/main/java/academy/backend/market_pulse/demo/concurrency/PortfolioExceptionsDemo.java). Сначала оба ответа успешны. Затем проверьте HTTP 500 от котировок, таймаут у курса и оба сбоя вместе. Строка расчёта появляется только при двух успехах. При ошибке `join()` бросает `CompletionException`. Для двух сбоев API допускает любую из причин.

Затем запустите `portfolio-value FAIL-QUOTES FAIL-FX FAIL-BOTH P2 --engine CF --trace`. Здесь ошибки приходят по HTTP. Для FAIL-BOTH сервис сохраняет обе причины, чтобы было понятно, кому сообщить о сбое. Для P2 в том же запуске получится 2100 RUB. Откройте [PortfolioService.evaluateBatch](../../../src/main/java/academy/backend/market_pulse/service/portfolio/PortfolioService.java) и найдите, где ошибка привязывается к конкретному портфелю. Комментарий NOTICE указывает возможное место для fallback. Вернитесь на **24**.

На **47** данные первого запроса уже готовы. Предложите группе назвать того, кто разбудит поток. На **48** появляется ответ, а на **49** поток снова получает carrier и продолжает чтение. Попросите найти в консоли оба `server received` до выдачи первого ответа. Следующее нажатие разрешит ответы, оба клиента получат HTTP 200. **По времени** снимите дамп, пока сервер удерживает ответы, и найдите в нём `demo-vt-P1` и `demo-vt-P2`. [Точки останова, команды jcmd и JFR](Демо%20—%20виртуальные%20потоки.md). Вернувшись на **51**, спросите, где в этот момент находился стек ожидания.

## 4. Что меняется на виртуальных потоках

Со слайда **67** откройте [PortfolioServiceV3](../../../src/main/java/academy/backend/market_pulse/service/portfolio/PortfolioServiceV3.java). Он использует алгоритм V1 и создаёт виртуальный поток на задачу. Запустите P1 и P2 с `--engine VT --quote-limit 1 --trace`. В [PortfolioService.quotes](../../../src/main/java/academy/backend/market_pulse/service/portfolio/PortfolioService.java) найдите `acquire` перед обращением к поставщику и `release` в `finally`. Тот же семафор действует в V1 и V2. Квота 1 допускает один незавершённый запрос цен. Получение курсов может продолжаться независимо.

Откройте [VirtualThreadThroughputDemo.runBatch](../../../src/main/java/academy/backend/market_pulse/demo/concurrency/VirtualThreadThroughputDemo.java). Здесь один пайплайн `CompletableFuture` получает либо фиксированный пул, либо executor с виртуальным потоком на задачу. Запустите с `-XX:ActiveProcessorCount=4`. Сначала сравните задачи в секунду на вычислениях, затем на настоящих HTTP-запросах к локальному серверу, который задерживает ответ на 60 мс. Каждый исполнитель получает одинаковые 48 задач. Суммы в строках одного сценария должны совпасть. Спросите группу, кто может занять свободный carrier во время ожидания сети и что ограничивает параллелизм при непрерывных вычислениях.

В контрольном прогоне на JDK 25 для JVM были доступны четыре процессора. В таблице указаны задачи в секунду в двух раундах одной демонстрации.

| Нагрузка | Фиксированный пул из 4 потоков | Виртуальный поток на задачу |
|---|---|---|
| Вычисления | 725 и 740 | 735 и 746 |
| HTTP с задержкой 60 мс | 57 и 58 | 526 и 569 |

На занятии сравните цифры своего запуска. На вычислениях оба исполнителя делят одни и те же ядра. При ожидании HTTP каждый из четырёх платформенных потоков занят одним запросом, а виртуальные потоки могут освободить carrier для следующих запросов.

## 5. Самостоятельная работа

Предложите участникам выбрать одну из [четырёх карточек](Обзор%20практики.md). Счётчик просмотров подходит для разбора потерянного обновления, список подписок для выбора коллекции, квота поставщика для семафора, публикация котировки для видимости данных в Java Memory Model. В папке каждой карточки вместе лежат условие с вопросами, заготовка и тест самопроверки.

Пусть каждый воспроизведёт дефект командой из карточки и объяснит, какое чередование событий его вызывает. После исправления нужно повторить ту же проверку. На общем разборе попросите участника назвать гарантию, которую теперь даёт его решение.
