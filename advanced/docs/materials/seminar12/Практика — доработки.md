# Практика. Доработки оценки портфеля

Выберите одну карточку. Отведите около 20 минут на реализацию и проверку. Оценку одного портфеля (З1) и пакет с квотой (З3) можно взять для повторения после общего разбора. З5 можно закончить после занятия.

В корне репозитория откройте Maven-проект на JDK 25. Запустите команду выбранной карточки до первой правки, затем повторите её после реализации. В IDE те же проверки запускаются из `PracticeStarterChecks`, условия проверок находятся в `PracticeContracts`. Работайте в [TaskStarters.java](../../../src/test/java/academy/backend/market_pulse/portfolio/practice/TaskStarters.java).

В тестовых данных P1 содержит три бумаги по 100 RUB и две по 10 USD. При курсе 90 RUB за USD портфель стоит 2100 RUB.

## З1. Оценка одного портфеля

В Market Pulse пользователь открывает оценку портфеля в рублях. Модуль, который заказал отчёт, должен сразу получить стейдж с результатом и продолжить работу. После загрузки позиций уже известны нужные тикеры и валюты, поэтому котировки и курсы можно запросить независимо.

**Что должно быть видно.** Вызов возвращает незавершённый стейдж, пока ответы удерживаются. Позиции, котировки и курсы загружаются на исполнителе `io`. Оба запроса успевают начаться до выдачи ответов. После одного ответа стейдж всё ещё не готов, после обоих расчёт на `calc` даёт 2100 RUB. Проверка пропускает ответы в обоих порядках.

**Где начать.** `TaskStarters#evaluate`. Сопоставьте журнал стейджей с именами потоков и посмотрите, на каких исполнителях заготовка вызывает `loadPositions` и `calculateValue`.

```bash
mvn -pl advanced '-Dtest=PracticeStarterChecks#z1' test
```

Нарисуйте зависимости и подпишите, какие данные доступны на каждом переходе. Посмотрите на `thenCompose`, `thenCombineAsync` и перегрузки, которые принимают исполнителя.

## З2. Резервный поставщик

Во время техработ основной поставщик котировок может вернуть 503. Market Pulse может по-прежнему оценить портфель по резервным котировкам. Ответ 404 в этом сценарии означает, что основному источнику неизвестны запрошенные данные, поэтому он должен доходить до вызывающего кода.

**Что должно быть видно.** При 200 итог составляет 2100 RUB, резерв не вызывается. При 404 итоговый стейдж завершается ошибкой 404, резерв тоже не вызывается. При 503 резерв вызывается ровно один раз. При успехе резерва тестовый отчёт показывает 2460 RUB, при его отказе итоговый стейдж передаёт ошибку 502.

**Где начать.** `TaskStarters#evaluateWithBackup`. Найдите в `PortfolioValuation` операции `loadQuotes` и `loadBackupQuotes`.

```bash
mvn -pl advanced '-Dtest=PracticeStarterChecks#z2' test
```

<summary>Кубики для второй попытки</summary>

Где нужно сделать выбор по коду HTTP и какой тип имеет результат каждой ветки? Пригодятся `PortfolioHttpStatusException`, `exceptionallyCompose` и `failedFuture`. Проверьте отдельно число вызовов поставщика и результат стейджа.

## З3. Пакет портфелей с квотой

Пользователь запрашивает несколько отчётов за один раз. Клиент может загружать данные по разным портфелям конкурентно, но поставщик котировок допускает только N одновременных обращений. Итоговая таблица должна совпасть с порядком списка пользователя, в том числе в строках с ошибками.

**Что должно быть видно.** Для каждого портфеля оценка идёт на виртуальном потоке. При трёх портфелях и квоте 2 два запроса одновременно находятся у поставщика, третий ждёт. Проверка также использует квоту 1. При вводе `P1, bad-price, P2` результат P2 может быть рассчитан первым, однако итоговый список сохраняет порядок, а ошибка связана с `bad-price`.

**Где начать.** `TaskStarters#evaluateBatch` и `TaskStarters#evaluateOne`. В заготовке задачи исполняются по очереди, места для сбора результата и обработки ошибки уже есть.

```bash
mvn -pl advanced '-Dtest=PracticeStarterChecks#z3' test
```

<details>
<summary>Кубики для второй попытки</summary>

Отдельно решите, где подать работающие на виртуальных потоках задачи, какую часть операции ограничить квотой и в каком порядке собрать результаты. Рассмотрите исполнитель «виртуальный поток на задачу», `Semaphore` и список `Future`.

</details>

## З4. Целостный снимок

Пользователь читает последний готовый отчёт, пока фоновый пересчёт загружает свежие данные. Ему нужно сразу показать согласованные версию, позиции и итог, иначе заголовок отчёта и его строки могут относиться к разным обновлениям.

**Что должно быть видно.** До первой публикации `currentSnapshot()` возвращает `null`. Пока пересчёт версии 2 удерживается, чтение возвращает версию 1 с её позициями и итогом. После публикации видна версия 2 целиком. Уже прочитанный снимок версии 1 сохраняет своё содержимое, а изменение исходного списка позиций после публикации не меняет новый снимок.

**Где начать.** `TaskStarters#publishSnapshot` и `TaskStarters#currentSnapshot`. Посмотрите, что уже хранится в `PortfolioSnapshot` и как `PortfolioReport` обрабатывает список позиций.

```bash
mvn -pl advanced '-Dtest=PracticeStarterChecks#z4' test
```

<details>
<summary>Кубики для второй попытки</summary>

Назовите момент, когда новый отчёт должен стать виден читателю. В какой момент уже готовы все поля? Сравните неизменяемый снимок с `AtomicReference` и короткую публикацию под блокировкой чтения и записи.

</details>

## З5. Выдача по готовности

При обработке большого списка Market Pulse может показывать строки по мере расчёта. Если источник задержал данные для первого портфеля, пользователь всё равно должен увидеть уже готовую оценку другого портфеля и узнать, какой портфель не найден.

**Что должно быть видно.** Пока P1 удерживается, получатель получает строку P2 с итогом 2100 RUB и ошибку 404 с ID `missing`. Эти две строки могут прийти в любом порядке. После разблокировки поступает P1. Для каждого входного портфеля получатель вызывается один раз.

**Где начать.** `TaskStarters#forEachReady`. Сначала проверьте порядок на модели в памяти, затем тем же контрактом на локальном HTTP-сервере.

```bash
mvn -pl advanced '-Dtest=PracticeStarterChecks#z5*' test
```

<details>
<summary>Кубики для второй попытки</summary>

Кто может сообщить о следующей завершившейся задаче, если первая поданная задача ещё ждёт? Изучите `ExecutorCompletionService`, `Callable` и `PortfolioResult`. Подумайте, где лучше связать результат или ошибку с ID.

</details>
